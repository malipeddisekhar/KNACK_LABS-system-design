1. Controlled Fault & Misconfiguration Diagnosis
--------------------------------------------------------------------------------
- Component: API bootstrap entrypoint (api/src/main.ts)
- Root Cause / Defect:
  The application parsed the platform-assigned PORT from environment variables
  (via ConfigService), but line 39 contained a hardcoded port:
    await app.listen(3000, '0.0.0.0');
- Observed BREAK Symptom:
  When the deployment platform assigned PORT=43127, the application continued
  listening on port 3000. Requests sent to the platform-assigned port 43127
  failed with ECONNREFUSED, causing health check failures and deployment rollbacks.

2. Code Remediation
--------------------------------------------------------------------------------
- api/src/main.ts:
  Restored dynamic platform port binding:
  ```diff
  -  // BREAK simulation: intentionally ignore the platform-assigned PORT.
  -  await app.listen(3000, '0.0.0.0');
  +  await app.listen(resolvedPort, '0.0.0.0');
  ```
  Where `resolvedPort = port ?? 3000`, bound to `0.0.0.0` for container networking.

- api/Dockerfile:
  Updated default runner CMD to execute Node directly instead of npm:
  ```diff
  -CMD ["npm", "run", "start:prod"]
  +CMD ["node", "dist/main.js"]
  ```
  Ensures Node runs as PID 1, receiving OS SIGTERM directly without intermediate
  shell/npm signal swallowing, enabling clean zero-exit-code graceful termination.

- .github/workflows/ci.yml:
  Added Docker Buildx `load: true` and an automated container runtime verification step
  with isolated test services, testing `/health`, `/ready` (200 & 503), port binding,
  and SIGTERM shutdown within the CI pipeline.
