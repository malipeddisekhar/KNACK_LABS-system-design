5. CI Bugfix & Prisma 7 Configuration Resolution:
   - Root Cause: Default `prisma7.config.ts` defines `url: env('DATABASE_URL')`. In CI, `DATABASE_URL` is omitted to enforce test isolation. Running `npx prisma generate` without `--config` caused Prisma 7 CLI to load `prisma7.config.ts` and fail with `PrismaConfigEnvError: Cannot resolve environment variable: DATABASE_URL`.
   - Resolution: Configured `npx prisma generate --config prisma7.test.config.ts`. This directly activates `prisma7.test.config.ts`, enforcing that `TEST_DATABASE_URL` is explicitly set and matches `url_shortener_test` exactly.
   - Compatibility: Verified locally that `prisma generate --config prisma7.test.config.ts` is fully compatible and generates the client into `src/generated/prisma` in ~55ms.

6. CI Bugfix & Jest ESM Module Loading Resolution:
   - Root Cause: In NestJS v12, `@nestjs/common`, `@nestjs/core`, and `@nestjs/testing` are published with `"type": "module"` (pure ES modules). In Jest 30 on Node.js 22, Jest's CommonJS loader (`CjsLoader`) cannot synchronously `require()` ES modules because `SourceTextModule.prototype.hasAsyncGraph` is only available in Node 24.9+. Because `jest.config.ts` lacked `extensionsToTreatAsEsm: ['.ts']` and `ts-jest` lacked `{ useESM: true }`, Jest compiled TypeScript test files into CommonJS and tried to `require('@nestjs/common')`, resulting in `createRequireEsmError: Must use import to load ES Module`.
   - Resolution:
     1. Updated `api/jest.config.ts` and `api/test/jest-e2e.json` with `extensionsToTreatAsEsm: ['.ts']` and configured `ts-jest` with `useESM: true` and `tsconfig: { module: 'ESNext' }`. This allows Jest to load test modules natively as ES modules via Node's VM modules runner (`node --experimental-vm-modules`).
     2. Updated `api/test/setup-test-db.ts` to export global `jest` via `import { jest } from '@jest/globals'; (globalThis as any).jest = jest;` so that all existing tests and assertions (`jest.fn()`, `jest.Mock`) continue working seamlessly without requiring code changes to individual test files.
     3. Ensured `__dirname` in `setup-test-db.ts` is safely derived using `fileURLToPath(import.meta.url)` in ESM contexts while preserving CommonJS backward compatibility.
