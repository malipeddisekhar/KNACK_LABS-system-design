2. Multi-Stage Dockerfile Architecture:
   - Stage 1: `dependencies` (node:22-bookworm-slim)

     * Copies package*.json.
     * Executes `npm ci --omit=dev` for reproducible production dependencies.
     * Installs `prisma@7.10.1` and `dotenv@18.0.9` into node_modules via `npm install --no-save` so one-off migration jobs run offline without devDependencies.
   - Stage 2: `builder` (node:22-bookworm-slim)
     * Installs full dependencies via `npm ci`.
     * Copies `prisma7.config.ts` and `prisma/`.
     * Generates Prisma 7 client into `src/generated/prisma` via `npx prisma generate`.
     * Compiles NestJS application into `dist/` (including `dist/generated/prisma`) via `npm run build`.
   - Stage 3: `runner` (node:22-bookworm-slim)
     * Minimal production runtime environment (`NODE_ENV=production`, `PORT=3000`).
     * Places local binaries on path (`ENV PATH="/usr/src/app/node_modules/.bin:$PATH"`).
     * Copies `node_modules` from `dependencies`.
     * Copies `package.json` for npm script execution.
     * Copies `dist` from `builder`.
     * Copies `prisma7.config.ts` and `prisma/` for one-off migration job.
     * Runs as non-root user (`USER node`).
     * Exposes port 3000.
     * Default CMD: `["npm", "run", "start:prod"]`.

3. Three Supported Execution Commands:
   - Command 1 (API): `npm run start:prod` (boots NestJS API via dist/main.js on 0.0.0.0:3000 without starting consumer)

   - Command 3 (Migration Job): `prisma migrate deploy` or `npx prisma migrate deploy` (runs standalone one-off migration using production DATABASE_URL and prisma7.config.ts)
