# Interlude: Healthcare.gov — 55 Contractors, Zero Integration Plan

## 1. Case Study Synthesis
On launch day (October 1, 2013), only 6 people successfully enrolled in health insurance across the entire United States out of millions attempting. Over 55 prime contractors and subcontractors had built technically sophisticated subsystems, each with passing unit tests. Yet the entire system collapsed because nobody owned the whole and zero end-to-end integration mapping existed.

---

## 2. Answers to Reflection Questions

### Question 1: Why were 55 detailed contractor plans not enough? What does a single unified dependency graph provide?
- **The Local Optimization Trap:** Each contractor's project plan modeled their own internal deliverables (e.g. Identity Verification, Eligibility Engine, Plan Comparison, Payment Gateway). But software does not fail within isolated components; it fails at the **handoff boundaries between components**.
- **What a Unified Dependency Graph Provides:**
  1. **Explicit Interface Contracts:** Formally defines the exact data schemas, token standards, and error payloads exchanged across service boundaries (e.g., ensuring the session token generated by Contractor A can be parsed by Contractor B).
  2. **End-to-End Critical Path Visibility:** Exposes the sequential bottleneck that dictates system availability. If identity verification is slow or down, the entire downstream eligibility and checkout chain halts.
  3. **Shared Failure Mode Invariants:** Establishes cross-system timeouts and circuit breakers so a sluggish third-party database does not cascade into complete front-door HTTP timeouts.
- Without a unified DAG, 55 teams build 55 puzzle pieces that do not fit together.

### Question 2: If brought in on Day 2, what is the FIRST thing you would do?
- **Do Not Start by Fixing Tickets:** Triaging random bug reports in Jira while the architecture is unmapped is futile; you end up fixing symptoms while the underlying systemic integration failure remains.
- **The Correct First Action (Process & System Mapping):**
  1. **Map the Architecture & Trace the Data Flow:** Draw the end-to-end dependency DAG from the browser request through every contractor service, database, and federal data hub.
  2. **Identify the Minimal Critical Path:** Determine the thinnest possible vertical slice required for one user to search, select a plan, and purchase insurance.
  3. **Instrument Boundary Telemetry:** Add distributed tracing (correlation IDs) at every contractor boundary to pinpoint exactly where requests drop, format mismatches occur, or timeouts trigger.
  4. **Stabilize Incrementally:** Lock down and verify that single end-to-end path with automated integration tests before expanding to edge cases, admin tools, or secondary features.
